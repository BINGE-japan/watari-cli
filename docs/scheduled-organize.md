# 記憶の整理を定期実行する（cron などからの無人実行）

ワタリの記憶の整理は `watari chat` の起動時に自動で走るため、通常は追加の設定は不要です。
パソコンの前にいない夜間などにも整理させたい場合は、OS のスケジューラ（cron・systemd タイマー・
launchd・Windows タスクスケジューラなど）から `watari chat` を非対話モードで起動します。
watari-cli 自身はスケジューラを同梱しません — 起動のタイミングは外部に任せる設計です。

## しくみ

`watari chat` は、同梱の人格スキルと保存済みの記憶フォルダ付きで Pi を起動し、`--` より
後ろの引数をそのまま Pi に渡します。Pi には非対話モード（`--print` / `-p`: 渡したプロンプトを
最後まで実行して終了する）があり、TTY のない定期実行に向いています。

## レシピ（cron の例）

    # crontab -e — 毎日 4 時に実行
    0 4 * * * WATARI_HOME=/path/to/your/memory watari chat -- --no-session -p "記憶を整理して" >> /path/to/organize.log 2>&1

補足:

- **「記憶を整理して」は、同梱の人格スキルが記憶整理の合図として認識する言葉です。**
  この文字列のまま渡してください。
- **Pi に渡すものはすべて `--` の後ろに置きます。** `watari chat` 自身の引数は
  `--home` / `--runtime` / `--show` だけで、それ以外（`-p` や `--no-session`）は `--` の
  後ろに無いと「不明な引数」として弾かれます。実際に組み上がるコマンドは
  `watari chat --show -- --no-session -p "記憶を整理して"` で事前に確認できます。
- `-p` / `--print` と `--no-session` は Pi の実在のフラグです（インストール済みの
  `@earendil-works/pi-coding-agent --help` で確認済み）。`--no-session` を付けると
  実行がセッション履歴に残りません。履歴を残したい場合は外してください。
- **cron の行では `WATARI_HOME` を明示的に指定してください。** cron の環境変数は最小限の
  ため、保存済み設定が拾われることに頼らないのが確実です（同じユーザー・同じ `$HOME` で
  動くなら拾われますが、明示するほうが安全です）。
- **`pi` 本体をインストールして cron の PATH に置くことを推奨します。** `pi` が
  見つからないと `watari chat` は `npx -y @earendil-works/pi-coding-agent` に
  フォールバックしますが、毎回ネットワーク解決が走るため、定期実行には不向きです。
- この実行でどの AI モデルを使うかは Pi 側の設定です（Pi の設定ファイル、または
  `--provider` / `--model` を同じく `--` の後ろに渡します）。`watari chat` はモデルに
  関知しません。

## 実行されること

会話の中で「記憶を整理して」と頼んだときとまったく同じ手順です: エージェントが
`watari scan --json` で候補を読み、あとで役に立つものだけを選び、`watari ingest` で
記憶に追記し、`watari audit` で点検します。どこまで読んだかの記録・重複の除外・選別の
基準は、人が頼んだときと同一です（手順の正式な定義は同梱スキル
`src/watari_cli/skill/SKILL.md` にあります）。
