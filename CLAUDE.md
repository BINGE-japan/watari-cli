# watari-cli

Working on watari-cli? **Read `SPEC.md` first** — it states the project's goal,
requirements, scope, current status, and settled decisions, so the intent
doesn't have to be restated each session. Then `AGENTS.md` (development
discipline / safety boundary). Then read only the task-relevant bundled documents:
`src/watari_cli/skill/SCHEMA.md` for memory data changes, `SKILL.md` for persona and
safety boundaries, and `MEMORY.md` for memory selection and execution procedures.

Keep `SPEC.md` current: when a goal, scope, decision, or the status changes,
update it in the same change — it is the single source of intent, not a log to
let drift.
